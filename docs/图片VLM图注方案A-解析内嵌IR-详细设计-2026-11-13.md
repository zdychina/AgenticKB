# 方案 A 详细设计：VLM 图注内嵌 document_parse 产物（写入 Parse IR）

> 日期：2026-11-13 | 状态：设计稿（待评审）

> 背景：[调研纪要-挖掘模块深读与图片VLM入口-2026-11-13](调研纪要-挖掘模块深读与图片VLM入口-2026-11-13.md)

## 1. 目标与非目标

### 1.1 目标

1. 图片（PNG/JPEG 等内嵌图）在**解析阶段**由多模态大模型生成图注，图注作为**知识快照本体的一部分**沉淀进 Parse IR（`FigureAsset.derived_annotations`）。
2. 下游零感知联动：`segment_compile` 见"有图注的 figure"即成片（复用现有 `_emit_figure` 路径），`retrieval_unit_project` 按现有 `figure → figure_caption` 矩阵生成检索单元。
3. 幂等与确定性：同一文档重跑不重复调用 VLM、不产生快照漂移（图注缓存层保证）。
4. 默认提示词与默认模型开箱可用，支持配置覆盖。
5. 独立 PNG 文件可作为输入源被解析并生成图注检索单元（后期工作包）。

### 1.2 非目标

- 不做 OCR/扫描件识别（扫描 PDF 守卫维持现状：无文本层 → FAILED + 需 OCR；`cloud_vlm` 槽位另立项目）。
- 不做图表数值结构化（chart series 解析）、不做图片相似度检索。
- 不改 legacy 链（`ImageCaptioner`/`parse_segment_handler` 维持原样直至删除）。
- 不在本方案内做图注质量的人工审核环（diagnostics 可见性先行）。

## 2. 现状与核心约束

### 2.2 核心设计矛盾与解法

**矛盾**：Parse IR 是不可变、内容寻址、指纹确定性的产物；VLM 输出是随机的。直接把 VLM 结果写进 IR 会破坏"同输入同 IR 字节"的不变量，导致每次重跑产生新 IR、新快照，幂等探针（同 `(document_id, source_raw_hash, parser_fingerprint)` 复用）失效。

**解法：双层 IR + 图注缓存层。**

- **核心 IR（core IR）**：解析器 + normalizer + reconciler 产出的确定性 IR，保持现有内容寻址与复用语义，**不含 VLM 输出**。影子服务照旧持久化（解析指纹、质量门、replay 均针对 core IR）。
- **增强 IR（augmented IR）**：`core IR + derived_annotations 注入` 后的整体 JSON，作为**第二个内容寻址制品**落 parse bucket（同 `artifact_class=parse_ir`，sha256 自然不同）；**快照绑定增强 IR**（快照的 parse_ir_ref 指向它，读侧 `ir_access.load_parsed_document` 无改动）。
- **图注缓存层（caption cache）**：VLM 图注按稳定键落 PG，重跑命中缓存 → 增强 IR 字节稳定 → 快照幂等不漂移。

## 3. 总体架构

### 3.1 图注增强子步骤在解析编排中的位置

```
DocumentParseService.execute（parse_operator/service.py）
  ├─ 幂等探针 / 扫描件守卫 / .doc→docx          （不变）
  ├─ 逐 backend ShadowParseService.execute       （不变，产出 core IR + backend_raw）
  ├─ 质量决策 PASS/WARN                           （不变，指标针对 core IR）
  ├─ ★ 图注增强子步骤（新，仅决策 PASS/WARN 后执行）
  │     1. 读 core IR，收集"无文本 figure 元素 + 二进制资产引用"
  │     2. 逐图查 caption cache → 未命中者批量调 VLM（LlmTaskClient 异步通道）
  │     3. 组装 augmented IR（deep copy + FigureAsset.derived_annotations 注入）
  │     4. augmented IR 内容寻址落 parse bucket（复用制品持久化助手）
  │     5. caption 结果（成功/失败/缓存命中计数）写 parse run metadata_json.caption_stats
  └─ SnapshotCommitService.commit                 （绑定 augmented IR；指纹组成见 §3.3）
```

- **状态机不新增状态**（避免 `shadow_parse` 状态契约与 asset_parse_runs CHECK 变更）：图注进度通过 parse run `metadata_json.caption_stats` + workflow 节点事件 `output_summary` 暴露。
- VLM 全量失败 → 放弃增强，augmented = core，照常提交快照（降级不阻断，对齐 FALLBACK 纪律）；diagnostics 记 `figure_caption_ready=false`。

### 3.2 图注缓存层（caption cache）

**键**（唯一确定性来源）：

```
cache_key = sha256(
    domain
    + source_raw_hash          # 冻结输入的原始内容哈希
    + parser_fingerprint       # 解析指纹变 → element 序可能漂移，必须隔离
    + figure_element_id        # 稳定 id "{scope}-e-{order_index:05d}"（parse_ir/ids.py:23）
    + model_fingerprint        # 模型 id
    + prompt_version           # 提示词版本号（见 §4.2）
)
```

**表 DDL 草案**（域库）：

```sql
CREATE TABLE asset_figure_caption_cache (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    cache_key     CHAR(64) NOT NULL UNIQUE,      -- 上述 sha256 hex
    domain        TEXT NOT NULL,
    source_raw_hash TEXT NOT NULL,
    figure_element_id TEXT NOT NULL,
    model         TEXT NOT NULL,
    prompt_version TEXT NOT NULL,
    caption_text  TEXT NOT NULL,                 -- VLM 图注正文
    image_sha256  TEXT NOT NULL,                 -- 送模图片字节哈希（审计/失效用）
    status        TEXT NOT NULL CHECK (status IN ('succeeded','failed')),
    error_code    TEXT,
    llm_task_id   TEXT,                          -- provenance 溯源
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_figcap_source ON asset_figure_caption_cache (domain, source_raw_hash);
```

- `failed` 行**不缓存**失败结论（下轮重试），仅 succeeded 落缓存；`image_sha256` 与请求时实际字节不符视为失效（防御解析器升级换图）。
- 迁移：`maintenance/database_upgrade` 新增 manifest 条目（框架现成：manifest + ledger + 校验，`python -m mining.maintenance.database_upgrade` 容器内执行）。
- **方案 B 共用本表**（见姊妹文档），两方案数据不分裂。

### 3.3 快照指纹组成变更（关键）

`effective_pipeline_fingerprint` 现为确定性管线指纹之和。本方案追加：

```
caption_fingerprint = "vlm-caption@<prompt_version>:<model>"      # 图注关闭时：无此段
                     + ":" + sha256(排序后 (element_id, caption_text) 列表)
```

- 关闭图注 → 指纹与现状**完全一致**（golden 回归字节不变的保证）。
- 开启图注 → 缓存命中时 caption 集稳定 → 指纹稳定 → 快照幂等；模型/提示词升级或图注内容变化 → 新指纹 → 新快照（正确的版本演进语义）。
- `parser_fingerprint` **不含** VLM（VLM 不是解析器，幂等探针不受影响：同源重跑不重新解析，只做缓存注入）。

### 3.4 augmented IR 的注入契约

```python
# FigureAsset.derived_annotations（契约已有字段，types.py:201）
{
  "vlm_caption": {
    "kind": "vlm_caption",
    "text": "<图注正文>",
    "model": "glm-4.5v",
    "prompt_version": "vlm-figure-caption-1",
    "native_caption_ref": "<原生图注 element_id | null>",   # prompt 参考过的原生图注
    "llm_task_id": "<provenance>",
    "generated_at": "<ISO8601>"
  }
}
```

- 只写 `derived_annotations`，**不触碰** FigureAsset 其余字段（契约"不得覆盖原图"纪律）。
- IR schema 校验（`parse_ir/schema.py`）对 derived_annotations 已是宽容结构，不新增强制校验；新增一条**语义校验**：`derived_annotations.vlm_caption` 存在时 figure 元素文本不得为空由消费侧保证（编译器读注成片，见 §5）。

### 3.5 重放（replay）路径

- `backend_raw → normalize → core IR` 的 replay 语义不变（确定性）。
- 增强 IR 的重放 = core IR 重放 + 缓存注入（同 cache_key 重取）；缓存行缺失且图注开关开启时，replay 报 `caption_cache_miss` 并降级为 core IR——**replay 永不隐式调 VLM**（保证重放确定性）。

## 4. 配置面与提示词契约

### 4.1 参数（document_parse 算子 params 扩展）

`workflow/operators/catalog.py` 中 `document_parse` 的 `paramSchemaJson` 增加嵌套组 `imageCaption`，对应新 pydantic 模型：

| 参数 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 总开关（默认关 = 现网行为字节不变） |
| `model` | `"glm-4.5v"` | 多模态模型 id，直传 llm_service |
| `promptOverride` | `null` | 覆盖默认提示词（覆盖即视为新 prompt_version = 用户自定义哈希） |
| `maxImagesPerDoc` | `20` | 每文档上限（沿用现 ImageCaptioner 默认） |
| `maxImagesPerRun` | `200` | 单 Run 总上限（成本护栏，超出记 warning 并截断） |
| `minImageBytes` | `1024` | 过小图片跳过（图标/装饰） |
| `callMode` | 继承 `MiningConfig.llm_call_mode` | async 任务通道 / sync 直连回退 |

- 模板（presets）**不启用**图注参数——4 套官方预置的 manifest 字节保持不变；启用路径 = 复制模板为自定义 workflow 后开参数（画布可编辑 `document_parse` 参数）。是否增设官方 `image_assets` 预置为**开放决策点**（见 §10）。
- `runOverrides` 白名单（现仅 maxWorkers/executionMode/publishOnPartialFailure）**不扩**，避免运行期改模型造成指纹混乱。

### 4.2 默认提示词（契约常量，版本化）

沿用现 `ImageCaptioner` 默认提示词作为 v1 契约（`prompt_version = "vlm-figure-caption-1"`），落在 `mining/infra/llm_templates.py`（与现有模板同址，单一来源）：

```
system: 你是技术文档图注助手。
user:   请用一两句中文描述这张图在技术文档中的含义。
        关注图中的结构、标注、流程或关键对象；不要编造看不清的细节。
        只输出图注正文，不要前缀「图注：」。
        [可选追加] 文档中的原始图注/表注（可参考）：<native_caption>
```

- prompt 版本号进 `cache_key` 与 `caption_fingerprint`：升级提示词 = 全量新缓存 = 新快照版本，旧快照不受影响。

## 7. 独立 PNG 文件支持（后期工作包 P2）

- **直通 adapter**（推荐）：新增 `image_passthrough` parser（parser_id，`_PIPELINE_FACTORIES` 注册 normalizer 对）：输入 image/png|jpeg|gif → 产最小 IR：单容器（`dom_document` 或新增 `image` 容器语义映射进现有 9 种）+ 1 个 figure 元素（EvidenceSpan.native_ref 记文件 sha256）+ FigureAsset + binary_assets。**不调 VLM、确定性**——图注由本方案的解析后增强步骤统一生成。
- Router：`_CLOUD_VLM_MIMES` 中的 image/* 改路由到 image_passthrough；`cloud_vlm` 占位槽保留给真正的云端 OCR/VLM 解析（另一项目）。
- 上传白名单已含 image/png|jpeg|gif（`safe_intake.py:77-79`），无需改。
- 此后独立 PNG 全链路 = 上传 → 直通解析 → VLM 图注 → figure 片段 → figure_caption 检索单元。

## 8. LLM 调用层

- 复用 `LlmTaskClient`（异步任务通道，不吞错）+ `llm_service.providers.multimodal.build_vision_user_message`。
- 图片物化：按 binary_assets 引用从对象存储流式读 → run workdir 临时目录（`run_workdir` 模式，`{run_id}/figcap/{sha256}.png`）→ 以本地路径入 vision message；Run 结束统一清理。
- `idempotency_key = sha256("figcap" + model + prompt_version + image_sha256)`——**全载荷哈希**纪律（对齐 `llm_generation.py:144` 修复后的口径），服务端防重。
- 批量：按 `LlmTaskClient` 批量提交/单一 deadline 轮询（默认 180s/批）；每文档顺序处理控制在 `maxImagesPerDoc`；3 次退避重试。
- 失败语义：单图失败 → 该图无图注（不缓存失败），继续其余图；全量失败 → 降级 core IR 提交，Run 不失败。

## 10. 灰度、回退与开放决策

- **灰度**：参数默认关 → 自定义 workflow 试点（单 KB）→ 视质量决定是否出官方 `image_assets` 预置。
- **回退**：关闭参数即回现状；caption cache 表与增强 IR 制品留存无害（不参与任何现状路径）；快照指纹因含 caption_fingerprint，关闭后回落现状指纹，自动回到旧快照复用轨道。
- **开放决策点**：
  1. 是否增设官方预置 `system-image-assets`（建议：试点后再定）。
  2. 缓存 TTL/容量治理（建议：先无限期，附 CLI 清理工具，仿 source_locator replay 的运维形态）。
  3. `caption_stats` 是否上 `GET /api/kb/{kb_id}/parse-result` 出生证明视图（建议：是，字段小改）。

## 11. 风险

| 风险 | 缓解 |
|---|---|
| VLM 幻觉图注污染检索单元 | 提示词纪律（不编造、只描述）；`structure_json.caption_source` 可追溯；后续可加质量门（图注与原生 caption 矛盾检测）作 P3 |
| 解析耗时上升（每文档 ≤20 图 × 秒级） | document zone 文档级并行天然摊薄；缓存命中后近零成本；maxImagesPerRun 总护栏 |
| LLM 成本 | 三层限额（每文档/每 Run/字节下限）；diagnostics 全量计数 |
| 增大 IR 体积 | 图注 ≤ 两句中文，单图 <300B，可控 |
| 缓存与解析器升级错配 | cache_key 含 parser_fingerprint + image_sha256 双保险 |
