## 二、数据模型

### 2.1 表：`semantic_object_artifact_refs`

```sql
-- 迁移 024（id core/20261119_014，编号以实施日为准）/ 启动链 kb/schemas/024 同文
CREATE TABLE IF NOT EXISTS semantic_object_artifact_refs (
    id          TEXT PRIMARY KEY,             -- sor_<16hex>，应用生成
    object_id   TEXT NOT NULL REFERENCES semantic_objects(id) ON DELETE CASCADE,
    artifact_id TEXT NOT NULL,                -- kb_artifacts.artifact_id，跨族软引用不建 FK
    target_key  TEXT NOT NULL DEFAULT '',     -- ''=制品整体；wiki=page_key；table=row_key（跨 revision 稳定）
    note        TEXT NOT NULL DEFAULT '',     -- 关联理由（可选，编辑判断的审计位；应用层限 500 字）
    ref_source  TEXT NOT NULL DEFAULT 'manual' CHECK (ref_source IN ('manual','auto_compile','auto_import')),
    created_by  TEXT NOT NULL REFERENCES kb_users(id),
    created_at  TEXT NOT NULL                 -- TEXT ISO（ontology 族口径，同 012）
    -- 无 updated_at：refs 只有建/删无更新，改备注=删了重建（评审④）
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_semobj_artifact_refs
    ON semantic_object_artifact_refs(object_id, artifact_id, target_key);
CREATE INDEX IF NOT EXISTS idx_semobj_refs_artifact
    ON semantic_object_artifact_refs(artifact_id);   -- 制品侧反查（制品删除清理、页/行详情列举）
```

设计要点：

- **FK 只建族内**：`object_id` 带 CASCADE（对象删=引用是关于它的事实，随删）；
  `artifact_id` 无 FK（对齐 kb 族惯例 + 制品删除由应用层同事务清理，见 §5）。
  `created_by` 沿用 012 族内 FK 惯例。
- **去重键** `(object_id, artifact_id, target_key)`：同对象同目标唯一；`''` 表示
  制品整体级（弱关联，允许但两侧 UI 都以页/行级为主推形态）。整体级与页/行级
  可并存于同一 `(object, artifact)`——展示侧按制品聚合，不算重复（评审⑦）。
- **不存 revision、不存目标标题快照**：读取时按 `current_revision` 现join 现解析
  （wiki=kb_wiki_pages、table=kb_table_rows），标题跟随最新——这是「跟随 current」
  语义的落法，也避免标题双写漂移。
- **`ref_source` 预留枚举建全**：一期只落 `manual`，二期自动对齐只加代码不改表
  （同 010 batches 通道枚举先例）。

## 三、权限模型

### 3.1 写权限：对象域管理员（与 67号 写口径一致）

- **建立/删除引用 = `can_manage_domain_ontology`（site admin 或对象库域的 domain admin）**，
  与本体线一切写操作同门槛——不引入"制品 editor 可写对象侧数据"的旁路。
- 创建时额外校验制品存在且 `kind IN ('table','wiki')`，404 不泄露他域制品存在性。

### 3.2 同域约束（一期）

`artifact.domain_id == ontology_library.domain` 方可建引用，422 `cross_domain_forbidden`。

推导：制品权限是「site/domain admin 全通 → 制品成员 → public 放大」三级，对象读是
域成员级。若允许跨域，制品侧读者（非对象域成员）看 ref 里的对象名即越权，须引入
wiki `unit_source` 式双侧独立判定+过滤的复杂度；而同域约束下——

- 域管理员建引用 ⇒ 对制品天然全通（域管理员对同域制品全权），目标选择器无需二次授权；
- 对象域成员读 refs ⇒ 制品至少可判定可见性（public 或成员与否），服务端按制品
  可见性过滤即可，无跨域泄露面。

同域已覆盖当前核心网场景（域内命令表/wiki 讲域内网元对象）。跨域策展延后到有真实诉求。

### 3.3 读权限：两侧各自口径，服务端过滤 + 反探测

| 读取面 | 入口权限 | 制品/对象可见性处理 |
|---|---|---|
| 对象的 refs 列表（UI/抽屉） | 对象读=域成员 | 只返回当前用户**可见**的制品（visibility=public 或制品成员或 admin）；不可见的引用整行不出现（对齐制品「非成员 404 反探测」原则，不显示"有 N 条你看不见"） |
| 制品页/行的相关对象（UI） | 制品读（成员/public/admin） | 同域约束下制品读者未必是对象域成员；对象信息（名称/本体名）仅域成员可见，非成员该 ref 降级为「对象不可见」占位（同 wiki unit_source 双重权限先例） |
| MCP `artifact_refs` 摘要 | 钥匙域成员（既有） | 再按 `mcp_key_open_artifacts` 开放子集过滤——制品对 Agent 的暴露面=钥匙显式勾选（008 口径），未开放的制品引用不出现 |

## 四、API（落 mining `/api/kb/ontology/*`，与 67号 同前缀同风格）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/ontology/objects/{object_id}/refs` | GET | refs 列表（当前用户制品可见性过滤后）；每条含 artifact 标题/kind/status、目标解析结果（wiki 页 title / table 行主键值）、`degraded` 原因（§5 矩阵）；`limit` 默认 100 + `truncated` 标记（评审⑤，69号 search/objects 同款） |
| `/ontology/objects/{object_id}/refs` | POST | `{artifact_id, target_key?, note?}`；校验同域/目标存在于 current revision（422 附 key 清单前 20 个）；重复 409 |
| `/ontology/objects/{object_id}/refs/{ref_id}` | DELETE | 删除单条；域管理员 |
| `/ontology/artifact-refs` | GET | **制品侧反查**（评审①）：`?artifact_id=&target_key=`（target_key 可省=该制品全部引用，含整体级）；权限=制品读+对象域成员双重口径（§3.3 第 2 行）；同 limit/truncated |
| `/ontology/objects/{object_id}/neighbors` | GET（扩展） | 响应 object 卡新增 `artifact_refs` 摘要：`[{artifact_id, artifact_title, kind, target_title, artifact_status, degraded}]` 上限 20 + `artifact_refs_truncated`（degraded 条目 `target_title=null`）；过滤按**当前用户**的制品可见性（与 refs 列表同一套，§3.3 第 1 行） |
| `/api/kb/mcp-tools/ontology/object-neighbors` | 既有端点扩展 | 同样带 refs 摘要，但过滤按**钥匙 `open_artifacts` 开放子集**（§3.3 第 3 行）；工具 docstring 补 artifact_refs 说明（Agent 才知道入口存在，评审⑦）；**不新增 POST 子路径，不动 auth_guard 豁免集** |

制品侧 UI（wiki 页头/表格行详情/制品级 chips）走 `GET /ontology/artifact-refs`
反查，**不新增 `/api/artifacts/*` 端点**——引用数据的属主在对象线，制品侧只是
查询视图（读也只此一条路，写入口仅对象侧一套）。

目标选择器数据源：同域制品列表（复用制品列表 API 按 domain 过滤）+ 制品 current
revision 的页/行清单（复用既有 wiki pages / table rows 读端点，权限天然带齐）。
**行选择必须按 row_key/关键字搜索**——万行级表格不可翻页选取，复用的 rows 端点
须带过滤参数（评审⑦）。

## 五、读侧降级矩阵（跟随 current 的代价边界）

| 情形 | 表现 |
|---|---|
| 制品已删除（引用行已被清理，理论残留兜底） | 不返回；防御性跳过 |
| 制品 `deprecated` | 正常返回 + status 徽标「已停服」 |
| 制品 draft（从未发布，current=rev0） | 正常返回 + 「草稿」徽标 |
| wiki 页在新 revision 被移除 / 表格行被删 | 返回该条 + `degraded: "target_missing"`（UI 灰显「目标已不存在」，保留可删） |
| 制品整体引用（target_key=''） | 永不 degraded（制品在即在） |
| 对象删除 | refs CASCADE 随删，无悬挂 |

无后台清理任务：degraded 是读时判定；制品删除时的主动清理见下。

**制品删除钩子**：制品真删（既有 artifact 删除流）同事务
`DELETE FROM semantic_object_artifact_refs WHERE artifact_id = $1`——引用是关于
对象的事实，但目标消亡后留着只会累积死行；这与对象侧 CASCADE 对称。
