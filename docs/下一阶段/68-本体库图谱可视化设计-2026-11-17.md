# 本体库图谱可视化设计（实例图渲染，68号）

> 承接 67号 §1.2「图可视化（schema 图 / 实例图渲染）——渲染二期做」的预留。
> 本期只做**实例图**：节点 = 语义对象（按本体着色），边 = 语义关系（带类型名）。

## 一、范围

### 1.1 做什么（MVP 三块）

| 块 | 内容 |
|---|---|
| 图数据端点 | `GET /libraries/{id}/graph`：一次返回库内全部对象节点 + 关系边（带过滤参数与规模护栏） |
| 图谱 Tab | 库详情页新增第四个 Tab「图谱」：G6 力导布局渲染、按本体着色、缩放拖拽 |
| 图上查看 | 点节点开右侧抽屉：对象详情（属性）+ 一度邻接（复用现有 NeighborList）；支持按本体开关过滤、关键字高亮、导出 PNG |

### 1.2 明确不做（MVP 边界）

| 不做 | 处理 |
|---|---|
| 图上直接编辑（拖拽建边/改名/删点） | 图谱只读；编辑仍走对象 Tab。图上编辑是后续独立课题 |
| schema 图（本体层小图：本体+边类型） | 本体/关系两个 Tab 已把类型层讲清楚；实例图才是缺口 |
| 大图分片 / 懒展开（按需拉邻居） | 全量一次拉取 + 规模护栏（§三）；超出引导过滤 |
| 多布局切换（DAG / 同心圆 / 径向） | 只用力导一种；布局切换后续按需加 |
| 节点大小按度数 / 按属性映射尺寸 | MVP 统一尺寸，着色已够区分 |
| 3D / 时间轴 / 全屏模式 | 不做 |

## 二、图数据端点设计

### 2.1 端点

```
GET /api/kb/ontology/libraries/{library_id}/graph
    ?ontology_ids=id1,id2      # 可选，只保留这些本体的对象（边两端都在集合内才保留）
    &limit=2000                # 节点数上限，默认 2000，上限也是 2000
```

- 权限：域成员可读（对齐其余读端点：域内只读成员也能看图）。
- 归属：mining 服务，`routes/ontology.py` + `db_ontology.get_library_graph`。

### 2.2 响应

```json
{
  "nodes": [
    { "id": "sobj_x", "name": "AMF", "ontology_id": "ont_a", "ontology_name": "网元" }
  ],
  "edges": [
    { "id": "srel_x", "source": "sobj_x", "target": "sobj_y",
      "ontology_relation_id": "orel_x", "relation_name": "承载" }
  ],
  "total_objects": 3,        // 过滤前库内对象总数（护栏提示用）
  "truncated": false         // 节点被 limit 截断时 true
}
```

- 节点不带 `attributes_json`（图载荷保持精简；点击后走既有 `GET /objects/{id}` 拉详情）。
- `ontology_ids` 过滤在 SQL 内完成（`WHERE so.ontology_id = ANY(%s)`），边按两端均在结果集内自然收敛（JOIN 即得，不用后过滤）。
- `truncated=true` 时前端顶部横幅提示「对象过多，已截断至 2000，请用本体过滤缩小范围」。

### 2.3 为什么不留前端自己拼分页

既有 `list_objects` / `list_semantic_relations` 都是分页端点，前端拼全图要 N 次请求且无原子性。单端点一次拿全还有第二收益：**演进方向 1（检索/MCP 消费图谱）将来直接复用同一端点**，不用再发明一次图查询。

## 三、规模护栏

| 项 | 取值 | 理由 |
|---|---|---|
| 节点上限 | 2000（`limit` 参数默认=最大=2000） | 力导布局 + 边标签在 2000 节点内交互尚可；真库当前量级（个位数十位）远未触及 |
| 超限行为 | 截断 + `truncated: true` | 不报错不拒绝——先给局部可看的图，引导过滤 |
| 边标签 | 保留（G6 自带 LOD 缩小时淡出） | 边类型名是图的核心信息 |

## 四、前端设计

### 4.1 入口与组件

- `OntologyLibraryDetailView.vue` 的 `el-tabs` 增加第四个 tab「图谱」（本体 / 关系 / 对象 / **图谱**）。
- 新组件 `kb-ui/src/components/ontology/GraphTab.vue`，props 对齐兄弟 Tab：`libraryId`、`ontologies`（父级已加载，图例与过滤开关直接用，不重复拉 schema）。
- API 层 `api/ontology.ts` 增 `getLibraryGraph(libraryId, params?)`；类型 `types/ontology.ts` 增 `LibraryGraph` / `GraphNode` / `GraphEdge`。

### 4.2 渲染（@antv/g6 ^5.1.1，依赖已在）

- 布局：力导（`force`）。节点按本体着色：前端维护 12 色板按 ontology 顺序分配，超 12 个本体循环取色。
- 边：带 `relation_name` 标签；箭头指向 target（语义关系是有向边，与建边方向语义一致）。
- 内置行为：画布拖拽、滚轮缩放、节点拖动；工具按钮：适应画布（fit）、导出 PNG（`graph.toDataURL()`）。
- 图例：本体色块 + 对象计数；点击色块 = 开/关该本体（**客户端过滤**：全量已在手，开关即时重渲染，不发新请求）。全关 = 空图 + 空态文案。
- 关键字：输入框匹配对象名——命中的节点高亮、其余淡化（客户端，不做删除）。
- 空态：库内无对象 → 引导文案「先到对象页创建或导入」；有对象无边 → 正常画散点。

### 4.3 节点点击抽屉

- 点击节点 → 右侧 `el-drawer`：
  - 对象摘要：名称 / 所属本体 / 属性表（`getObject`，按本体属性定义排序展示，对齐对象 Tab 详情形态）；
  - 一度邻接：**直接复用 `NeighborList.vue`**（已有出边/入边分组组件）。
- 抽屉随点击切换内容，不叠多层。

### 4.4 权限

图谱 Tab 对所有能进库详情页的人可见（成员只读本来就能读对象与关系，图只是同一数据的另一种呈现）。Tab 内无任何写操作。
