## 一、环境与前提

| 项 | 要求 |
|---|---|
| 环境 | 生产 `http://39.96.13.112:8080`（nginx 前端 + 五服务） |
| 账号 | **admin**（站点管理员，天然满足引用写权限）；权限边界验证需一个同域普通成员账号（如 test01） |
| 写权限口径 | 引用写入 = 对象库所在域的**域管理员**（站点管理员直接可写）；读 = 域成员 + 制品可见性双重过滤 |
| 同域约束 | 被引用制品必须与对象库**同域**——跨域制品在引用对话框的制品下拉里根本不出现 |
| 数据准备（一次） | ① 一个**表格制品**：加一列、插两行（如 命令列 `ADD POOL` / `DEL POOL`）；② 一个 **wiki 制品**：写两个页面。制品均建在 `cloud_core_network` 域。复用现有制品亦可 |

两个容易踩的坑（MCP 测试尤其）：

1. **制品须已发布**才能被钥匙「开放制品」勾选——候选 = 同域 + **已发布** + 当前用户可见；未发布的勾了也会被**静默剔除**（008 口径，`replace_open_artifacts` 行为）。发布另有前置门槛：**先填「使用说明」**（`usage_note`），否则 422 `usage_note_required` 挡发布（脚本首跑即踩此坑）；
2. 引用要先在前端建好（§二 A 步），MCP 侧只读不建。

## 二、前端测试路径

### A. 建引用（对象侧管理口）

1. 侧边栏「知识本体」→ 进库（如 `本体库01`）→ 「语义对象」Tab；
2. 找目标对象（如 `ADD POOL`）→ 行操作列点 **「引用」** → 弹「制品引用」对话框；
3. 新建表单连建三条，覆盖三种目标粒度：
   - **行级**：选表格制品 → 目标下拉自动切**远程搜索**（输入行键或列值片段如 `ADD`）→ 选一行 → 填关联理由 → 保存；
   - **页级**：选 wiki 制品 → 目标下拉直接列出版面（标题 ‖ page_key）→ 选一页 → 保存；
   - **制品整体级**：目标选「制品整体」→ 保存；
4. 列表应出现 3 条（行级/页级显示目标名，整体级显示「制品整体」）；点制品名可跳制品详情页。

### B. 对象卡计数 + 图谱只读

1. 对象 Tab 点开该对象详情抽屉 → 底部 **「被 3 个制品引用」**；域管理员看到「管理」按钮（回对话框），普通成员是「查看」；
2. 切「图谱」Tab → 点该对象节点 → 抽屉同样显示计数，按钮只有 **「查看」**——打开的对话框**只读**（无新建/删除表单；图谱是读面，`canWrite` 恒 false）。

### C. 制品侧反查 chips + 聚焦跳转

| 位置 | 显示内容 | 目标粒度 |
|---|---|---|
| 制品详情页标题下方 | 「相关对象（制品级）」 | 整体级引用 |
| wiki 制品阅读器选中某页后的页头 | 「相关对象：」 | 该页的页级引用 |
| 表格制品某行「编辑」对话框顶部 | 「相关对象：」 | 该行的行级引用 |

chips 点击 → 跳到对象所属库的图谱 Tab，目标节点**描边强调 + 视口居中**（复用 69号 focus 链路，不打开抽屉）。

> chips 在**没有任何引用时不渲染**（不留空白占位）；制品对当前用户不可见
> （private 且非成员）的引用在 chips 侧直接不出现，这是设计行为。

### D. 边界行为（可选）

- **降级灰显**：删掉被引用的那行 → **发布新版本** → 回对象 Tab「引用」列表，该条灰显「目标已不存在」，仍可删除；图谱抽屉计数仍含它；
- **权限收敛**：换普通成员账号 → 对象 Tab 无操作列/「引用」按钮，抽屉按钮变「查看」，图谱照旧只读；
- **422 可引用键提示**是防御路径——UI 选择器只给合法目标键，正常操作触发不了，不必刻意测。

## 三、MCP 消费测试

### 3.1 消费的是什么

70号 **不加新工具**：`get_semantic_neighbors` 的返回扩展了 `artifact_refs[]`
（该对象被哪些制品讲到：行级/页级/整体级，上限 20 + `artifact_refs_truncated`
截断标记），且**只包含这把钥匙显式开放的制品**（`mcp_key_open_artifacts` 子集
过滤：未授权的引用直接不出现，不报错）。工具 docstring 已提示 Agent
「要看制品内容用既有的 wiki/表格查询工具族」。

### 3.2 测法一：UI 配钥匙 + 外部 Agent 真实消费

1. 前端「MCP 接入」页 → 建钥匙（域选 `cloud_core_network`）→ **明文只显示这一次**，先复制；
2. 同页「**开放的知识制品**」段 → 勾上被引用且**已发布**的制品 → 保存；
3. 外部 Agent 接入——`http://39.96.13.112:9000/mcp` 外网可达，Claude Code 一行：
   ```bash
   claude mcp add --transport http cmkb http://39.96.13.112:9000/mcp \
     --header "Authorization: Bearer <明文>"
   ```
4. 问 Agent：「`ADD POOL` 在哪些制品里被讲到？」——应调 `get_semantic_neighbors`，返回里看到 `artifact_refs`（制品名、目标行键/页、状态，结构见 §四）；
5. **子集过滤正反验证**：回 UI 把该制品的勾去掉 → 再问一次 → `artifact_refs` 变空（邻接关系照常返回）。一正一反即 70号 MCP 语义的核心。

### 3.3 测法二：容器内脚本验收

仓库根备有脚本（未跟踪，与既有冒烟同模式、跑完自清理不留脏数据）：

| 脚本 | 覆盖 |
|---|---|
| `.smoke-ontology.py` 第 10 步 | refs HTTP 全周期：建表制品→插行→整体级/行级引用→neighbors 摘要→制品侧反查→422 valid_keys→行 q 过滤（评审⑦）→清理 |
| `.smoke-mcp-refs.py` | **MCP 消费专用**（11 项检查）：建临时钥匙→临时库+对象→已发布制品→行级+整体级两条引用→真 fastmcp 协议调 `get_semantic_neighbors`：**未授权断言 refs 为空 → 授权后断言 2 条且 target_key 对**→全量清理（引用→对象→本体→库→制品 deprecate+删→钥匙吊销+删） |

跑法（ssh stdin 灌入，避开远程引号地狱）：

```bash
ssh root@39.96.13.112 'docker exec -i -e PYTHONPATH=/app cmkb python -X utf8 -' < .smoke-mcp-refs.py
```

## 四、artifact_refs 字段参考

每条 `artifact_refs[i]` 共 7 个字段（`ontology_service.summarize_object_refs`）：

| 字段 | 含义 |
|---|---|
| `artifact_id` | 制品 id |
| `artifact_title` | 制品标题 |
| `kind` | `"table"` 或 `"wiki"` |
| `target_key` | 引用目标：`""` = 制品整体级；表格 = 行 `row_key`；wiki = 页 `page_key` |
| `target_title` | 目标的人类可读名：**wiki → 页 title；表格 → `row_key` 本身**（业务主键即展示名）；整体级恒 `null` |
| `artifact_status` | 制品状态（`active` / `deprecated` 等） |
| `degraded` | `null` = 健康；`"target_missing"` = 目标页/行在制品 current revision 已不存在（此时 `target_title` 为 `null`，引用仍保留可删） |

同级标记：**`artifact_refs_truncated`** —— 引用总数超过 20 条（摘要上限）时 `true`。

降级矩阵（设计文档 §五）：**整体级永不 degraded**（制品在即可引用）；页/行级跟随
current revision 现解析，缺席即降级。

混合形态返回示例（Agent 视角）：

```json
{
  "object": { "name": "ADD POOL", "ontology_name": "MMLCommand", "...": "…" },
  "outgoing": [ "…" ],
  "incoming": [ "…" ],
  "artifact_refs": [
    { "artifact_id": "art_bbe69431…", "artifact_title": "MML 命令表",
      "kind": "table", "target_key": "cmd-amf-001", "target_title": "cmd-amf-001",
      "artifact_status": "active", "degraded": null },
    { "artifact_id": "art_9f02…", "artifact_title": "AMF 开局指导",
      "kind": "wiki", "target_key": "page-config-steps", "target_title": "配置步骤",
      "artifact_status": "active", "degraded": null },
    { "artifact_id": "art_9f02…", "artifact_title": "AMF 开局指导",
      "kind": "wiki", "target_key": "", "target_title": null,
      "artifact_status": "deprecated", "degraded": null },
    { "artifact_id": "art_77a1…", "artifact_title": "旧割接手册",
      "kind": "table", "target_key": "row-gone-42", "target_title": null,
      "artifact_status": "active", "degraded": "target_missing" }
  ],
  "artifact_refs_truncated": false
}
```

四条分别示意：行级（`target_title`=row_key）、页级（=页标题）、整体级
（`target_key` 空串、`target_title` null 但 `degraded` 也是 null）、降级行
（目标已从最新版本移除）。

再叠一层 MCP 特有口径：经钥匙调用时，数组**只剩该钥匙开放制品**的引用
（未授权条目直接不出现，不是标灰）；授权行 ⊆ 钥匙主人读可见面（008 口径，
保存时静默剔除越权/未发布候选，读取时再校验一次防权限收缩窗口）。

## 五、权限速查

| 面 | 口径 |
|---|---|
| 引用写入（对象/图谱对话框） | 对象库所在域**域管理员**（站点管理员直通） |
| 对象侧 refs 列表/摘要 | 域成员 + 当前用户制品可见性过滤（不可见引用整行不出现） |
| 制品侧反查 chips | 制品读权限 + 对象域成员双重口径（非对象域成员 → `object_invisible` 占位） |
| MCP refs 摘要 | 钥匙 `open_artifacts` 开放子集 ⊆ 钥匙主人可见面；未开放制品的引用不出现 |
