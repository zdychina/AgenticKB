## 3 建议补充内容（可直接放入第 42 章）

（11-28 勘误：判定路径 1-3 的 UI 路径全部核实为真——`/llm?tab=tasks` 由 `LlmView.vue:821-824` 读 query.tab 生效、状态筛选含"死信"（`:471`，dead_letter）；`/settings` →"LLM 域覆盖"标签提供 embedding 的 model / base_url / api_key（`LlmDomainOverridesTab.vue:124-145`）；降级三件套名称全部真实（见下文降级段注记）。各步措辞需按随附注记修订后落地。）

**现象**：知识库大量文档"挖掘失败，等待重试"；LLM 任务中心死信堆积；任务错误含 `embedding result returned 0 vectors`。

**判定路径**：

1. `/llm?tab=tasks` 筛选"死信" → 看 `error_message` 是否为 `0 vectors`。
   （11-28 勘误：路径属实，但**任务列表页无 error_message 列**——需点进任务详情，在 attempts 错误框看（`LlmTaskDetailView.vue:351-352`）。条目落地时写"点开任务看错误信息"更准。）
2. `/settings` → `llm_service` 检查 `embedding` 段：`base_url`、`model`、鉴权头是否与当前环境匹配。
   （11-28 勘误：页面实际入口为 `/settings` →"LLM 域覆盖"标签；embedding 的 model / base_url / api_key 有表单字段（`LlmDomainOverridesTab.vue:124-145`），自定义请求头走 YAML 文本编辑。"鉴权头"在 UI 上对应 api_key 字段 + YAML headers，说法基本成立。）
3. 用平台外的 curl 对同一 endpoint 做最小验证（不带 `dimensions` 字段）：

```bash
curl -s -X POST "$EMBEDDING_URL" -H "Content-Type: application/json" \
     -H "$AUTH_HEADER" -d '{"model":"bge-m3","input":["hello"]}'
# 期望 data 数组非空且维度与库列一致
```

4. 若 `data` 非空但平台仍失败 → 检查平台是否把额外字段（如 `dimensions`）写进请求体（见 BUG-01）。
   （11-28 勘误：**BUG-01 已于 2026-11-24 修复**（commit `4527897`），且修复形态不是"删字段"而是 **`embedding.send_dimensions` 配置开关**（默认 `true`，`bigmodel_models.py:115-116`、`main.py:161-165`）：智谱 embedding-3 必须下发 `dimensions: 1024` 压维以匹配库列 `vector(1024)`；MaaS/bge-m3 等 `extra_forbidden` 网关需在配置设 `send_dimensions: false`。条目落地时本步应改写为"核对 `send_dimensions` 开关与网关类型是否匹配"。）

**临时降级（不需重启）**：

1. 新建/修改挖掘范式，改用 `轻量关键词资产`（`system-lexical-assets`，无向量节点）。
2. 知识库"设置"绑定该范式；检索范式绑定 `系统关键词证据检索`。
3. 重新挖掘 → 关键词检索可用（语义检索不可用，属预期降级）。

（11-28 勘误：**降级路径三件套全部核实为真**——`system-lexical-assets` ＝"轻量关键词资产"，流水线 ingest→parse→segment→project→persist→finalize 无 embedding 节点（`knowledge_mining/mining/workflow/presets.py:23-24`、`templates.py:3`）；"系统关键词证据检索"官方描述即"不要求 embedding 服务；配套轻量关键词资产"（`agent_serving_java/.../operator/paradigm/ParadigmService.java:204-206`）；"标准混合资产" ＝ `system-hybrid-assets` 官方默认。"语义检索不可用属预期降级"与范式设计一致。）

**恢复后**：切回 `标准混合资产` 并重新挖掘（建议配合"仅重试失败项"，见 BUG-06）。

（11-28 勘误：**"仅重试失败项，见 BUG-06"——引用失实，为本单最重要更正**。BUG-06 勘误后库侧"仅重试失败项"判为**不适用、未实施**（`BUG-06 修复记录.md:50`："勘误后 KB 侧维持现状，现有选择性挖掘即可达成"）。实际在场的两项等价能力：① KB 侧选择性挖掘——前端"筛选失败 → 多选 → 挖掘选中"（`document_ids` 圈定）；② LLM 侧任务批量重试 `POST /api/v1/tasks/retry-batch`（task_ids 多选或按状态圈定，`dry_run` 默认 True；前端"重试选中 / 重试本页全部"）。条目落地时此句应改为"配合选择性挖掘（筛选失败文档后多选重挖）或 LLM 任务批量重试"。）
