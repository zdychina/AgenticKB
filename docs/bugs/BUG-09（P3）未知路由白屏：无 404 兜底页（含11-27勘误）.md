# BUG-09（P3）未知路由白屏：无 404 兜底页

> 级别：P3（前端体验）
> 环境：AgenticKB v1.1.41 发现；2026-11-27 在 master（1.1.54）逐条核对
> 发现：2026-11-18；勘误：2026-11-27（见 §7——核心事实属实（P3 维持），三处更正）

## 1 现象

访问任意不存在的 SPA 路径（如 `/nonexistent`、`/kb/does-not-exist-xxx`）时，页面**完全空白**：侧边栏、头部都不渲染，控制台无报错，浏览器停在原 URL。

> 勘误（11-27）：`/kb/does-not-exist-xxx` 不在白屏之列——它命中 `kb/:kbId` 路由，走 `KbDetailView.vue:80-89` 的业务 404 态（EmptyState+重试/返回列表），与本报告 §4 的提醒一致。白屏仅限不匹配任何路由的路径（如 `/nope`、超出已定义层级的 `/kb/a/b/c`）。

## 2 复现

1. 登录后直接在地址栏访问 `http://<host>/#/nope`（或 history 模式的 `/nope`）。
2. 得到纯白页面，无任何提示，用户无法回到首页（只能手动改地址）。

> 勘误（11-27）：本项目路由为 history 模式（`router/index.ts:7` `createWebHistory()`），hash 写法 `/#/nope` 的 pathname 是 `/` → 正常渲染仪表盘，不白屏；复现应直接用 `/nope`。

## 3 根因

`kb-ui/src/router/index.ts` 只有具名路由，**没有 catch-all**：

- 全仓 `grep pathMatch` 无命中（Vue Router 4 的兜底写法是 `{ path: '/:pathMatch(.*)*', component: NotFound }`）；
- 无匹配时 `RouterView` 渲染空 → 由于布局组件挂在路由树内，外层布局也被跳过 → 白屏。

（11-27 核对：两点均属实——`App.vue:2-4` 根组件只有 `<router-view />`，`AppLayout.vue` 挂在 `/` 路由（`router/index.ts:17`）；已登录时 `to.name` 为 undefined 不在 `ADMIN_ROUTES`，守卫放行 → 确认白屏。未登录访问未知路径会被守卫踢到 `/login?redirect=…`（`router/index.ts:179-181`），故复现前提「登录后」正确。）

## 4 修复建议

在路由表末尾加兜底路由，并给一个"回首页/回上一页"的可操作页面：

```ts
{ path: '/:pathMatch(.*)*', name: 'not-found', component: () => import('@/views/NotFoundView.vue') }
```

`NotFoundView.vue` 建议：

- 文案："页面不存在或已被移除"；
- 两个按钮："返回首页"、"回到上一页"；
- 若检测到 `redirect` 查询参数与当前路径一致，提示"登录后跳转目标无效，已回首页"（与 M14 的 redirect 回跳逻辑联动，见 `LoginView.vue:76-79`）。

同时对 `/kb/:id` 这类资源路由：资源 404（后端反探测）已有页面级处理，请确认它们与"路由不存在"区分开，避免把无权限误导成"页面不存在"。

## 5 验证

1. 访问 `/nope` → 显示 404 页面，侧边栏可点，能回首页。
2. 访问 `/kb/<不存在的id>` → 仍显示"知识库不存在或无权访问"的业务态（不被兜底路由吞掉）。
3. 登录后带 `?redirect=/nope` → 登录成功后落到 404 页而不是白屏。
4. 直接访问 `/` 与正常页 → 不受影响。

## 7 勘误记录（2026-11-27 核对）

核心事实逐条核对**全部属实**，定级 P3 维持：

- 路由表无 catch-all：`router/index.ts:8-161` 全部为明确 path/name 的具名路由；
- 全仓 `grep pathMatch` 源码零命中（唯一命中为本报告自身两处）；
- 白屏机理成立：`App.vue` 根组件只有 `<router-view />`，`AppLayout.vue` 挂在 `/` 路由上（`router/index.ts:17`）；未知路径无匹配 → 无组件渲染 → 纯白，侧边栏头部均无；
- 复现前提「登录后」正确：未登录访问未知路径会被守卫重定向到 `/login?redirect=…`（`router/index.ts:179-181`），不白屏；
- 「控制台无报错」按生产构建成立——vue-router dev 构建会对无匹配路径打 `No match found for location with path` 警告，生产构建无输出。

原报三处更正：

1. **§1 现象举例 `/kb/does-not-exist-xxx` 不白屏**：它匹配 `kb/:kbId` 路由（`router/index.ts:56`），走 `KbDetailView.vue:80-89` 的业务 404 态（`loadError` → EmptyState+重试；无 kb → notFound+返回列表）——与本报告 §4 自己的提醒及 §5 验证 2 直接矛盾，该例应从 §1 删除；
2. **§2 复现主写法 `/#/nope` 不成立**：路由是 history 模式（`router/index.ts:7` `createWebHistory()`），`/#/nope` 的 pathname 是 `/` → 匹配 dashboard 正常渲染，hash 部分被忽略；只有 `/nope` 才白屏；
3. **`LoginView.vue:62-65` 行号定位错误**：`redirectAfterLogin` 实际在 76-79 行，62-65 行是 `toggleLang` 结尾与 `step`/`username` 声明。

## 8 修复记录（2026-11-27）

方案：catch-all 放 `/` 布局路由 children **末位**（相对路径 `:pathMatch(.*)*`，编译为 `/:pathMatch(.*)*`）而非 §4 建议的顶层写法——顶层会让 404 页失去侧边栏/头部，违反 §5.1「侧边栏可点」；具名路由按匹配得分天然优先，`kb/:kbId` 等资源路由不受影响，资源 404 仍走 `KbDetailView` 页面级业务态（§5.2）。未登录访问未知路径仍先被守卫送到 `/login?redirect=…`，登录后 `redirectAfterLogin` 原样 push → 落到 404 页（§5.3）。

| 文件 | 改动 |
|---|---|
| `kb-ui/src/router/index.ts` | children 末位新增 `not-found` 兜底路由（懒加载 NotFoundView），注释说明布局内放置与得分优先的理由 |
| `kb-ui/src/views/NotFoundView.vue` | 新增：EmptyState（WarningFilled）文案「页面不存在或已被移除」+「返回首页」「回到上一页」；无内部来路（直接地址栏进入，`history.state.back == null`）时隐藏「回到上一页」；「登录后跳转目标无效」识别两种来路——`redirect` 查询参数与当前路径一致（§4 建议的检测），或 `history.state.back` 为 `/login*`（redirectAfterLogin push 后 query 已清空，靠来路辨别；文案改「目标页面不存在」，因页面停留 404 而非自动回首页） |
