# 方案 B 详细设计：独立可选算子 image_caption_generate（workflow 层外挂）

> 姊妹方案：[方案A-解析内嵌IR](图片VLM图注方案A-解析内嵌IR-详细设计-2026-11-13.md)

## 0. 方案选型对照（A vs B）

| 维度 | A 解析内嵌 IR | **B 独立算子** |
|---|---|---|
| 图注沉淀位置 | 知识快照本体（IR derived_annotations） | Run 级产物（figure 补充切片 + 图注缓存） |
| 解析器改动 | 需要（IR 组装、指纹、增强制品） | **零** |
| 编译器改动 | 小（`_emit_figure` 认图注） | 零（算子自行产 figure 片段） |
| workflow 引擎改动 | 零 | 中（目录注册第 10 算子 + 模板） |
| 确定性边界 | 增强 IR 需缓存保幂等 | 切片层追加，快照指纹不变 |
| 重切/重投影复用图注 | ✅ 快照内天然复用 | 需重跑算子（缓存命中近零成本） |
| 降级语义 | 解析内降级（core IR 提交） | 算子级 FALLBACK（与 query_expansion 同构） |
| 生效粒度 | workflow 参数（document_parse 内） | 图上加减节点（画布级） |
| 首个可用格式 | PPTX（P0a） | **PPTX（零解析器改动，当期即可端到端）** |

选型建议：要"图注作为知识资产长期沉淀、跨 Run 稳定"选 A；要"最快上线、最小侵入、按图按需启用"选 B。两者共享图注缓存表与 P0 解析器抽取工作包，且可组合（A 已图注的 figure，B 自动 NOT_APPLICABLE 跳过）。

## 1. 目标与非目标

### 1.1 目标

1. 新增第 10 个内置算子 `image_caption_generate`：对快照 IR 中"无图注、无文本"的 figure 元素调用多模态大模型生成图注，并将图注固化为**补充 figure 切片**进入 SegmentStore，由现有 `retrieval_unit_project` 投影为 `figure_caption` 检索单元。
2. 全链路对解析器与编译器**零改动**；不触碰 Parse IR、不改变快照指纹组成。
3. FALLBACK 语义：VLM 不可用/失败时算子降级，基础资产完全不受影响（对齐 query_expansion_generate / hierarchical_summary_generate 的既有纪律）。
4. 幂等：同 Run 重跑/续跑不重复调 VLM、不重复插切片；切片追加按 figure 元素身份去重。
5. 默认提示词 + 默认模型（glm-4.5v）开箱可用，参数可覆盖。

### 1.2 非目标

- 不做 OCR/扫描件识别、图表数值结构化（同方案 A）。
- 不改 legacy 链。
- 不做图注写回 IR（那是方案 A 的职责；两者组合时 B 让位）。

## 2. 算子契约（MiningOperatorDef）

按 `workflow/operators/catalog.py` 的 `_SPECS` 规格注册：

```python
MiningOperatorDef(
    type="image_caption_generate",
    version="1",
    display_name="图片图注生成（VLM）",
    description="对快照中无图注的图片调用多模态大模型生成图注，"
                "补插 figure 切片供检索投影为 figure_caption 单元。",
    category="enhancement",
    zone=ExecutionZone.DOCUMENT,
    edit_policy=EditPolicy.EDITABLE,        # 与 query_expansion_generate 同级：可删可改参
    input_slots=[SlotDecl("documents", DOCUMENT_BATCH)],
    output_slots=[SlotDecl("documents", DOCUMENT_BATCH)],
    requires=frozenset({"parsed_segments"}),   # 由 segment_compile 提供
    provides=frozenset({"figure_captions"}),
    error_policy=ErrorPolicy.FALLBACK,
    unique=True,
)
```

- **图谱位置**（模板与画布的标准接法）：

```
input_ingest → document_parse → segment_compile
                                     ↓ documents
                       ★ image_caption_generate
                                     ↓ documents
                       retrieval_unit_project → embedding → asset_persist
                                                     ↓ finalizeInput
                                               mining_finalize → result
```

  排在 `retrieval_unit_project` **之前**：投影器从 SegmentStore 读全部切片（`list_for_snapshot`），补充 figure 切片自动进入投影矩阵 `figure → figure_caption`（`projector.py:30-40`），投影层零改动。若排在投影之后（如 query_expansion 的位置），算子就得自己写表示——放弃。
- **错误策略 FALLBACK**：handler 异常/LLM 全挂 → 节点事件 `fallback` + warnings，能力集不含 `figure_captions`，链条继续。

### 2.1 参数 schema（pydantic Options，注册进 OPTIONS_BY_OPERATOR）

| 参数 | 默认 | 说明 |
|---|---|---|
| `model` | `"glm-4.5v"` | 多模态模型 id |
| `promptOverride` | `null` | 覆盖默认提示词（自定义哈希进 prompt_version） |
| `maxImagesPerDoc` | `20` | 每文档上限 |
| `maxImagesPerRun` | `200` | 单 Run 总上限 |
| `minImageBytes` | `1024` | 小图跳过 |
| `includeNativeCaption` | `true` | 原生图注存在时拼进 prompt 作参考 |
| `attachNativeCaption` | `true` | 切片 raw_text 中原生图注在前、VLM 图注在后 |

默认提示词与方案 A **同一契约常量**（`vlm-figure-caption-1`，落 `infra/llm_templates.py` 单一来源），两方案提示词演进同步。

## 3. 执行机制

### 3.1 handler 流程（`workflow/handlers/document.py` 新增）

```
image_caption_generate_handler(state, runtime, params):
  1. bundle = state.context（MiningDocumentBundle）
     bundle.snapshot_ref 为空 → NOT_APPLICABLE（无快照，如跳过文档）
  2. ir = ir_access.load_parsed_document(snapshot_ref)     # 共享加载通道，sha256 校验
  3. figures = [f for f in ir.elements+structured_assets
                if f 是 figure 且 text/caption/derived_annotations 均空
                且 binary_assets 有对应字节引用]
     为空 → NOT_APPLICABLE（A 已图注或无图）
  4. 逐图查图注缓存（与 A 共用 asset_figure_caption_cache，同 cache_key 口径）
     未命中 → 物化字节（对象存储 → run workdir {run_id}/figcap/{sha256}.png）
           → LlmTaskClient.submit_chat(build_vision_user_message(...), model=...)
           → wait_for_tasks（单一 deadline，3 次退避）
           → 成功落缓存（llm_task_id 溯源），失败该图放弃（不缓存失败）
  5. captioned 非空 → 构造补充 figure 切片（§3.2）→ SegmentStore.append_figures_for_snapshot（幂等 upsert，§3.3）
  6. bundle.with_updates(compiled_segment_count += n, documents facts 增量)
     → state.with_context(bundle, capabilities={"figure_captions"})
  7. 部分成功 → SUCCESS + warnings[per-figure 失败清单]；全失败 → FALLBACK
```

- 异步驱动：handler 在 DocumentExecutor 工作线程同步执行，仓储/服务调用经 `async_bridge.run_sync`（与 RetrieProjectFacade 同构）。
- `idempotency_key = sha256("figcap" + model + prompt_version + image_sha256)`（全载荷哈希纪律，与 A 一致）。

### 3.2 补充 figure 切片的构造

对每个成功图注的 figure 元素产 `CompiledSegment`（复用编译器既有投影 `to_raw_segment_data`）：

| 字段 | 取值 |
|---|---|
| `block_type` | `figure`（兼容投影白名单已有） |
| `raw_text` | `[原生图注(可选)] + VLM 图注`（`attachNativeCaption` 控制） |
| `heading_chain` | figure 元素所在章节的标题链（由 IR parent_of 链回溯，与编译器同口径） |
| `element_links` | figure 的 EvidenceSpan（visual_region/native_ref），溯源不断链 |
| `structure_json` | `caption_source: "vlm"`、`vlm_model`、`figure_element_id`、`image_sha256`、`llm_task_id` |
| `token 计数` | 字符近似（与编译器同规则） |

**切片身份（防碰撞规则）**：编译器产出的 `segment_key = {document_key}#{segment_index}`，index 为 0..N-1 顺序整数。补充切片使用**独立编号空间**：

```
segment_key = f"{document_key}#f{figure_order}"    # figure_order = 本快照图注成功的 figure 按 IR 阅读序 0..M-1
segment_index = 无碰撞保留段：1_000_000 + figure_order（int 侧隔离，排序恒在编译切片之后）
```

- 字符串键后缀 `f` 与纯数字 index 天然不撞；int 侧用保留段隔离，避免任何按 int 比较的路径（排序/合并）误混。
- `figure_order` 由"快照 IR 内容（确定）+ 图注缓存（确定）"决定 → 重跑同键同序，幂等成立。
- **实现校验点**：落地前核对 `asset_raw_segments` 的 CHECK/唯一约束与 `seg merge` 身份逻辑（`core.py:_merge_segments` 按 `(document_key, segment_index)` 对齐）确认保留段无冲突；本算子在链尾单向追加，不参与多前驱合并，风险面小。

### 3.4 与下游的联动（全部零改动，逐项核对）

| 环节 | 行为 |
|---|---|
| `retrieval_unit_project` | 读 SegmentStore 全量切片 → 补充 figure 切片按矩阵产 `figure_caption` 表示；`representation_id` 锚 snapshot 的规则照常生效 |
| `asset_persist` structure_projection | figure 片段照常产结构节点（document→section→segment→figure 路径）与 element_links 溯源 |
| embedding | `figure_caption` 是否 dense_eligible 沿用现有 embedding policy 矩阵 |
| readiness | figure_caption lexical 表示计入 `search_ready`；无 dense 不拖累 `dense_ready`（policy 决定） |
| `mining_finalize` | 无感知：Build 摘要的切片计数自然包含补充切片 |
| 与方案 A 组合 | A 已写入 `derived_annotations.vlm_caption` 的 figure 在 B 的第 3 步被过滤 → NOT_APPLICABLE，不双重图注 |

### 3.5 断点续跑与重复运行

- **Run 内 resume**：GlobalExecutor/DocumentExecutor 的节点级事件复用规则同样适用——`image_caption_generate` 节点已有 completed/fallback 事件即跳过重跑（`reusable_node_result` 读事件能力集）。
- **文档重跑（retry_rejected / force_redo）**：算子重执行 → 缓存命中（近零 LLM 成本）→ `append_figures_for_snapshot` 同键 upsert（净变更 0）。
- **FALLBACK 后的补救**：fallback 事件会被 resume 复用，不会自动重试 VLM；需重试时走文档级 retry 或 force_redo 重跑（与 query_expansion 行为一致，文档需写明）。

## 4. 目录与版本兼容

- `workflow/operators/catalog.py::_SPECS` 追加第 10 项；`OPTIONS_BY_OPERATOR` 注册 `ImageCaptionOptions`；`handler_registry` 注册 handler。
- **catalogVersion 处理（关键）**：`MiningWorkflowRuntime` 校验 `catalogVersion`（runtime.py:30-31 现支持 schema 2.0 / catalog 1）。追加算子属于目录演进：
  - 运行时支持的 catalog 版本升为 2，**同时向后兼容 catalog 1**（旧冻结 manifest 不含新算子，不受影响；校验逻辑只要求 manifest.catalogVersion ≤ 支持值）。
  - 存量已发布 workflow 版本的 manifest 字节不变，不需要重发布。
  - 实现时以 `tests/test_mining_operator_catalog.py` 契约测试锁定：catalog 1 manifest 在支持 2 的运行时下可执行。
- 模板：不改动现有 4 套官方预置（manifest 字节稳定）。**可选**新增第 5 套预置 `system-image-assets`（= hybrid + 本算子插在 retrieval_unit_project 前），走 `ensure_workflow_library` 幂等 seed 与漂移重发布机制——是否增设为开放决策点（建议：试点验证图注质量后再定，初期用"复制 hybrid 为自定义 workflow + 画布加节点"路径试用）。

## 5. 图注缓存（与 A 共用）

表结构、cache_key 口径、prompt 契约常量与方案 A §3.2/§4.2 **完全一致**（`asset_figure_caption_cache`，DDL 见 A 文档）。差异仅写入时机：A 在解析编排内写，B 在算子内写。先上 B 后上 A 时缓存无缝继承，反之亦然。

## 6. 前置工作包（与 A 共享）

- **P0-抽取**：PDF/DOCX 图片字节抽取（PPTX 已具备）——见方案 A §6。**B 的分期能力**：P0 完成前，B 对 PPTX 文档即已全链路可用（快照 IR 里现成的 figure + binary_assets）；PDF/DOCX 的图注能力随 P0 各格式落地自动解锁，算子零改动。
- **P2-独立 PNG**：`image_passthrough` 直通 adapter（见方案 A §7）。B 与该 adapter 组合同样能让独立 PNG 走完"上传→解析→图注算子→figure 切片→检索单元"全链路。

## 8. 灰度、回退

- **灰度**：算子注册即向后兼容（旧图不选不执行）→ 复制 hybrid 为自定义 workflow 试点 → 可选官方预置。
- **回退**：从图上删节点即回现状；已追加的 figure 切片随下次 `retrieval_unit_project` 的快照级替换/文档重挖自然清理（SegmentStore 快照级写入口径一致）；极端情况 purge 文档重建。

## 9. 风险

| 风险 | 缓解 |
|---|---|
| 直写 final 表（无 staging）的中间态可见性 | 与 segment_compile 现行口径一致；同键幂等 upsert；Build 校验兜底；文档写明 |
| segment_index 保留段与未知约束冲突 | §3.2 实现校验点：落地前核对 CHECK/唯一约束与合并身份逻辑 |
| catalogVersion 升级兼容 | 契约测试锁定旧 manifest 可执行（§4） |
| bundle 计数漂移（compiled_segment_count 增量） | handler 内 with_updates 同步修正；finalize 的 Build 摘要以库内实测为准 |
| VLM 幻觉 | 与 A 相同：提示词纪律 + structure_json 全量 provenance（caption_source/vlm_model/llm_task_id） |
| fallback 后无人重试 | diagnostics 计数 + Run trace warnings 可见；补救路径文档化（§3.5） |
